1. REQUIREMENTS                           *ghostty-smart-splits-requirements*

Neovim 0.11+, smart-splits.nvim, Ghostty 1.3+ on macOS, and macOS Automation
permission. Run Neovim locally inside Ghostty. Configure Ghostty's nvim key
table before starting Neovim; the ready-to-copy configuration is in
examples/ghostty.conf.

==============================================================================
2. SETUP                                         *ghostty-smart-splits-setup*

SMART-SPLITS V2

Configure smart-splits normally, then call setup() once at startup with the
Neovim pane focused:
>
  require('smart-splits').setup({}) -- Existing options and mappings.
  require('ghostty-smart-splits').setup({})
<
The v2 setup preserves existing smart-splits options and sets
`multiplexer_integration = 'ghostty'` and `at_edge = 'stop'`. It returns false
when the session is unsupported or the focused terminal cannot be attached.

SMART-SPLITS V3 (EXPERIMENTAL)

Use smart-splits.nvim's `v3` branch and select the backend:
>
  require('smart-splits').setup({
    mux = { backend = 'smart-splits-backend-ghostty' },
    move = { at_edge = 'stop' },
  })
<
Do not call the v2 root module's setup() with v3. Core activates the selected
backend during setup; start Neovim with its Ghostty pane focused. The v3
protocol may change before release.

CONFIGURATION

The only backend option is `key_table`, the name of the Ghostty key table used
while Neovim is active. It defaults to `nvim` and must be a non-empty string.
Use the v2 root module or the v3 backend module, depending on the integration:
>
  -- v2
  require('ghostty-smart-splits').setup({ key_table = 'editor' })

  -- v3: configure the backend before smart-splits setup.
  require('smart-splits-backend-ghostty').setup({ key_table = 'editor' })
<
The configuration step is side-effect-free: it does not run AppleScript,
attach to Ghostty, or register autocommands. In v2, the root setup continues
with attachment and activation; in v3, core activates the selected backend.

==============================================================================
3. API                                             *ghostty-smart-splits-api*

require('ghostty-smart-splits').claim_keys()
    Push the configured Ghostty key table if it is not already claimed.

require('ghostty-smart-splits').release_keys()
    Pop the table claimed by this instance. Keys are also released on
    VimSuspend and VimLeavePre, and claimed again on VimEnter and VimResume.

:checkhealth ghostty-smart-splits
    Check local prerequisites. With v3, :checkhealth smart-splits also
    includes backend diagnostics.

The underscore names ghostty_smart_splits and ghostty_smart_splits.health
remain deprecated aliases for the dashed module and health names.

==============================================================================
4. LIMITATIONS                            *ghostty-smart-splits-limitations*

macOS only. AppleScript calls are synchronous and time out after one second.
The initial Ghostty terminal comes from the focused pane; later actions keep
using that terminal instead of following focus changes.

Do not stack another Ghostty key table above this one while Neovim is active.
If a crash or config reload leaves stale state, the Ghostty action
deactivate_all_key_tables can recover it, but clears every table.

Native performable:goto_split bindings can give Ghostty priority. This plugin
is for Neovim-first navigation.
